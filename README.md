# Introduction

This is my collection of Advent-of-Code solutions written in Rust.

Tools used:

Clippy for linting:

```sh
cargo clippy
```

Fmt for formatting:

```sh
cargo fmt
```

# Input files

It is assumed that the input data for each problem is stored in a file with a file structure like 
`/AdventOfCode-Input/<year>/day<xx>.txt`, where that parent folder is placed in the root folder of this repo.
If your naming, file structure or location is different, the paths in the `run` function in `src/lib.rs`
needs to be modified accordingly.

# Running the solver

To run a certain day, simply pass year followed by day as arguments. For example, if running through cargo:

```sh
cargo run 2024 14
```

For benchmarking, make sure to pass the `release` flag:

```sh
cargo run --release 2024 14
```

The day argument supports both single and double digit format for the first nine days, i.e. both ```8``` and
```08``` works.

# Unit tests

Each solver has contains its own unit tests, with primarily the official test vector from the puzzle
description, complemented with custom made test vectors mostly generated by LLM:s for better coverage.

```sh
cargo test
```

To run only the unit tests and not the regression tests:

```sh
cargo test --lib
```

# Regression tests

When an answer to a puzzle is known, a regression test will be triggered from `tests/regression.rs` if
there is a corresponding `day<DD>.answer` file in the input files directory. The content of those files
are expected to be the answer for both parts separated by a line containing exactly `---`. Each part
may span multiple lines, in case of grid / ASCII art answers. For example:

```text
12345
---
..X.
.X..
.XX.
```

If the file has no `---` separator, the entire content is treated as the answer for part 1, and part 2
is compared against an empty string.

Some days are slow to test, so to speed it up it can be run in release mode:

```sh
cargo test --release --test regression
```

To see the summary of how many days were verified, and how many were skipped due to no local input,
add the `nocapture` flag:

```sh
cargo test --release --test regression -- --nocapture
```

Behavior:

- Only days with a corresponding pair of `day<DD>.txt` and `day<DD>.answer` files in the input files
  directory are tested.
- Days that have both input files present, but the solution is not yet implemented (the solver fails
  with `Day not implemented` or `Year not implemented`) are not counted as failures.
- If the input file direcory is missing entirely, the test reports it and passes (nothing to check).
- All mismatches are collected and reported together at the end, with a per-part `got` vs `expected`
  diff, rather than failing on the first.
- A solver returning `Err` is reported as a failure.
